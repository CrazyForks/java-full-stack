# docs/AGENTS.md

本文件定义 `docs/` 文档维护规则。

## 1. 文档定位

- `docs/` 是学习内容与技术决策的权威来源。
- 实践进度状态（含卡片状态规则）以 [实践计划与进度](10-实战产品蓝图/实践计划/README.md) 为唯一来源，本目录不重复声明。
- 文档修改必须服务学习闭环：准确、可验证、可追溯。

## 2. 模板

- 阶段零至阶段七保留七段式骨架，段内可按内容需要重排：
  - 快速入门。
  - 精简大纲。
  - 学习内容详情。
  - 坑点提醒。
  - 本节自检。
  - 本节配套思考题。
  - 常见面试题。
- 阶段八使用独立模板，不套阶段零至七格式。
- 不删除既有 `⏸️ 短期可以不学` 框、代码块、面试题三层答法、前端对照。
- 速览区给出代码示例即可，示例用于展示形态，不承担可运行承诺；可运行前提（依赖、开关）归正文。坑点提醒为 `##` 级，与学习内容详情平级。
- `⏸️ 短期可以不学` 框不与小节标题重复声明同一取舍。
- 上述标准约束新写与后续优化的讲义；存量各讲按需优化时对齐，不做批量回溯。

## 3. 写作规则

- 简体中文。
- 术语首次出现必须解释，只出现一次的专业词同样必须解释。
- 机制类内容优先用 Mermaid，内嵌于 Markdown 文档；不引入外部图表工具或导出独立 HTML。
- Mermaid 类型按内容选择：流程用 flowchart，时序用 sequenceDiagram，状态用 stateDiagram，类关系用 classDiagram，排期用 gantt。
- Mermaid 节点文本包含半角引号或括号时，用 `["..."]` 包裹或改中文标点。
- 类比必须采用“生活版 → 技术结论”双段式。
- 面向前端背景读者时，优先使用 NestJS、npm、RxJS、浏览器请求链路做对照。
- 全文修改完成后，反向扫尾一遍尚未解释的专业缩写与术语。
- 易混词成对辨析（如幂等 vs 去重、实体 vs 值对象）。
- 后文推理依赖的术语与概念，必须在其被依赖之前解释到位；「详见后文」式的悬空引用视为断层。
- 引用精确到「阶段 + 讲次」，消除同名编号歧义。
- 标题与小节名的承诺与内容名实相符。

## 4. 内容质量

- 不堆术语。
- 不重复解释同一概念。
- 快速入门只做导航和最低理解门槛。
- 正文负责机制、场景、代价、工程落点。
- 坑点提醒只保留正文未集中解决的风险。
- 面试题不得引入正文没有解释过的新概念。
- 核心原理写成推演（分情形 + 图示或推演文本 + 分工），不是一句结论；断言补适用条件，数字给来源、判断给依据。
- 实体先于机制：先讲「是什么、怎么用」，再讲「为什么好」；示例不得出现未定义的类型或字段。
- 生命周期类机制讲完整闭环（含失败分支）。
- 同一主题散落多处时归位：核心主题独立成节，重复信息源合一；对比表置于各概念展开之后。
- 自检与正文双向对齐：考的必须教过，新增重点同步进自检。
- 内容查漏以「学完应能回答的问题」清单反向核查，不依赖通读印象。

## 5. 链接与重命名

- 重命名文件或目录必须同步审计交叉链接。
- 修改文档结构后使用 `rg` 检查旧路径、旧标题、旧文件名。
- 实践卡片完成记录必须写明日期、结果和可复现证据。
- 未验证内容不得标记完成。

## 6. 产品实现导航

- [后端实现导航树](10-实战产品蓝图/product-tree.md) 是面向学习的代码地图，按 `boot-server/` 的真实目录层级记录模块、源码和测试入口。
- 目录是分层依据：类写在实际所在的包中，同一文件只列一次；商品等业务域通过对应的 `controller`、`service`、`mapper`、`entity` 等目录体现，不另建虚拟目录汇总或重复列类。
- 描述只保留定位和理解代码所需的职责、关键行为与验证入口，优先短句；接口细节、技术原理和完成证据留在对应文档或卡片，不把导航树写成第二份实现记录。
- 里程碑、卡片编号及「待开始 / 进行中 / 已完成」等进度状态只引用 [实践计划与进度](10-实战产品蓝图/实践计划/README.md)，不在导航树复制维护，也不以源码存在推断卡片完成。
- 新增、删除或调整后端模块、关键接口、数据模型、安全机制或测试入口时，同步核对导航树中的路径与描述；计划中的功能不能写成已实现。
