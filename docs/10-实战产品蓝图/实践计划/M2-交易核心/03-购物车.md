# M2-03：购物车

返回 [实践计划与进度](../README.md)。

## 目标

登录用户能把 SKU 加入购物车，并查看、修改数量、移除条目。

## 范围

- t_cart_item（id、user_id、sku_id、quantity、create_time、update_time；`user_id + sku_id` 唯一索引）。
- POST /cart/items 加购（请求数量是正增量；重复加购原子累加）。
- GET /cart 查看本人购物车（聚合 SKU 现价信息）。
- PUT /cart/items/{id} 修改数量。
- DELETE /cart/items/{id} 移除。
- 接口归类「仅认证」，且只能操作本人数据（横向越权防护，非本人条目按 404/40400 处理）。

## 并发与数量契约

- `quantity` 是正整数，允许范围为 `1` 至 `999`。加购和改量传入 `0`、负数、非整数或超过上限时返回 `400/40000`。
- `POST /cart/items` 的 `quantity` 表示增加量；同一用户、同一 SKU 的并发加购必须最终只有一条购物车记录，数量等于初始数量加全部成功请求的增量之和。
- 实现采用原子语义：先以 `UPDATE ... SET quantity = quantity + :delta WHERE user_id = :userId AND sku_id = :skuId` 尝试累加；未命中时插入。插入遇到唯一键冲突后，重新执行一次条件累加。禁止「先查再写」导致丢失更新，也不能把唯一键异常直接暴露给客户端。
- `PUT /cart/items/{id}` 的 `quantity` 是设置后的绝对值，不承担删除语义；数量为 `0` 必须返回 400。删除只通过 `DELETE /cart/items/{id}` 完成。
- 加购、改量不校验库存，也不在本卡预扣库存；库存校验与预扣只在 M2-05 下单事务执行。

## 学习点

唯一索引兜底并发、聚合查询、本人数据隔离。

## 验收

1. 未登录访问 401/40100。
2. 加购、累加、改量、移除全链路可用。
3. 两个及以上并发加购同一 SKU 后仅有一条记录，最终数量精确等于全部成功增量之和；不出现重复键异常或丢失更新。
4. `quantity` 的 0、负数、非整数和超过 999 均返回 400/40000；更新为 0 不删除条目。
5. 操作他人条目返回 404/40400。
6. `mvnw.cmd -pl services/user-service -am test` 在 JDK 25 下通过。

## 不做

- 不做 Redis 购物车（M2.5）。
- 不做选中与结算接口（C 端接入时前端组合）。
- 加购时不校验库存（下单时才扣减）。
