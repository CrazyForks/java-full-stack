# M2-04：库存表与管理

返回 [实践计划与进度](../README.md)。

## 目标

管理员能为 SKU 设置库存，预扣模型（total/locked）与条件更新语义就位。

## 范围

- t_stock（sku_id 主键、total_count、locked_count、update_time）。
- PUT /stocks/{skuId} 设置总量（product:manage 权限，条件更新校验调整后 total - locked 不小于 0，违反返回 409/40900）。
- GET /stocks/{skuId} 管理查询（返回 total、locked、available）。

## 接口与并发约定

- `PUT` 的 `total` 仅接受非负 JSON 整数，例如 `{"total": 10}`；这是绝对总量，客户端即使附带 `locked` 或 `available` 字段也不会改变它们。首次设置创建库存行，后续设置覆盖总量；多个合法的绝对设置请求并发时，最后完成的条件更新生效。
- `GET` 对尚未配置库存的 SKU 返回 `404/40400`；`PUT` 对不存在或已逻辑删除的 SKU 返回 `404/40400`。未认证返回 `401/40100`，无 `product:manage` 权限返回 `403/40300`，非法总量返回 `400/40000`。
- 库存行的唯一主键解决并发首次设置；插入发生唯一键竞争后，在新事务内按最新锁定量重试条件更新。总量低于已锁定量时返回 `409/40900`，锁定量和原总量均保持不变。

## 学习点

预扣库存模型（total/locked/available）、数据库条件更新防超卖的基础语义。

## 验收

1. 管理员设置库存成功并可查询。
2. 将总量调到低于已锁定的请求被拒（409/40900），locked 不被破坏。
3. 普通用户 403/40300。
4. `./mvnw -pl services/user-service -am test` 通过。

## 不做

- 不做 Redis Lua 预扣（M2.5 出现压测信号后）。
- 不做库存分桶（M4）。
- 不做扣减接口（05 下单事务内完成）。
