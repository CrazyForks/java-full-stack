# M2-10：发货与完成

返回 [实践计划与进度](../README.md)。

## 目标

管理员能对 PAID 订单发货，用户确认收货后订单完成，状态机全链路闭环。

## 范围

- 新增 order:manage 权限码并关联 ADMIN（schema 增量）。
- GET /admin/orders B 端全量订单分页（order:manage）。
- POST /admin/orders/{id}/ship 发货（状态机条件更新 PAID→SHIPPED，order:manage）。
- POST /orders/{id}/confirm 确认收货（本人，SHIPPED→DONE）。

## 学习点

状态机完整矩阵（CREATED → PAID → SHIPPED → DONE / CANCELLED）、B 端与 C 端接口的权限分类。

## 验收

1. 全链路 CREATED→PAID→SHIPPED→DONE 顺序流转可走通。
2. 乱序迁移（如 CREATED 直接 SHIPPED、DONE 后 SHIPPED）返回 409/40900。
3. 普通用户访问 B 端接口 403/40300。
4. `./mvnw -pl services/user-service -am test` 通过。

## 不做

- 不做物流单号与收货地址（蓝图 ER 无此字段）。
- 不做 B 端前端页面（前端接入里程碑统一做）。

## 完成记录

日期：2026-09-20

提交：本次提交（`feat: 完成订单履约状态链`）。

测试与接口证据：在 `boot-server/` 使用 Oracle JDK 25.0.4.1 执行 `./mvnw -q -pl services/user-service -am clean test`，28 份 Surefire 报告共 128 个测试，失败、错误、跳过均为 0；`git diff --check` 通过。

- 全链路：真实 HTTP 从创建订单、模拟支付、管理员发货到订单本人确认收货完整走通 `CREATED → PAID → SHIPPED → DONE`；后台 `GET /admin/orders` 按创建时间和 ID 倒序分页，并返回订单所有者 `userId`。
- 状态门：CREATED 直接发货或确认、PAID 直接确认、重复发货、重复确认以及 DONE 后再次发货均返回 `409/40900`；所有写入使用当前状态条件更新，并发下只有一次合法迁移。
- 权限与隔离：`order:manage` 由 `PermissionCodes` 集中持有，schema 幂等创建并关联 ADMIN；未登录访问后台接口返回 `401/40100`，普通用户返回 `403/40300`。确认收货同时校验订单 ID、所有者与 `SHIPPED`，他人订单返回 `404/40400`。
- 静态值审计：Security 仅引用集中权限常量；`order:manage` 在 DDL 中作为 RBAC 持久化映射保留，接口路径在 Controller 与 Security 内部匹配器就近声明，状态值由 `OrderStatus` 统一拥有。本卡未新增部署配置、错误码、角色码或共享存储键。
