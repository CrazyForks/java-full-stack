# M2-07：订单查询

返回 [实践计划与进度](../README.md)。

## 目标

用户能查看自己的订单列表与订单详情（含明细）。

## 范围

- GET /orders 本人订单分页（按创建时间倒序）。
- GET /orders/{id} 订单 + 明细聚合 DTO。
- 接口归类「仅认证」，本人数据隔离（他人订单按 404/40400 处理，不暴露存在性）。

## 学习点

聚合查询、订单明细关联、横向越权防护。

## 验收

1. 登录后能看到自己的订单列表与详情，明细含快照价。
2. 访问他人订单返回 404/40400。
3. `./mvnw -pl services/user-service -am test` 通过。

## 不做

- 不做 B 端全量订单管理（10 卡片）。
- 不做按状态筛选（后续卡片）。
- 不做导出。

## 完成记录

日期：2026-09-20

提交：本次提交（`feat: 新增本人订单查询`）。

测试与接口证据：在 `boot-server/` 使用 Oracle JDK 25.0.4.1 执行 `./mvnw -q -pl services/user-service -am clean test`，23 份 Surefire 报告共 103 个测试，失败、错误、跳过均为 0；`git diff --check` 通过。

- 真实 HTTP：`GET /orders` 只返回当前 JWT 用户的订单，按创建时间和 ID 倒序分页；`GET /orders/{id}` 返回订单头和明细，SKU 改价后仍返回下单时的快照价。未登录查询返回 `401/40100`，查询他人或不存在订单统一返回 `404/40400`，非法分页参数返回 `400/40000`。
- 分层与回归：订单应用层依赖只读查询端口，不依赖 MyBatis Mapper 或持久化 Entity；OpenAPI JSON 同时包含订单创建、列表和详情路径。本卡未新增配置值、错误码、权限码或共享存储键。
