# M2-09：订单取消

返回 [实践计划与进度](../README.md)。

## 目标

用户能取消未支付订单并释放预扣库存；已支付订单不可取消。

## 范围

- POST /orders/{id}/cancel（本人订单；状态机条件更新 CREATED→CANCELLED；释放库存 locked 减 n；同一 @Transactional）。
- PAID 或 CANCELLED 状态下取消返回 409/40900 非法状态迁移。

## 学习点

状态机迁移矩阵、补偿性库存释放。

## 验收

1. 取消后订单为 CANCELLED，locked 归还、可用库存恢复。
2. 对 PAID 订单取消返回 409/40900。
3. 重复取消返回 409/40900。
4. `./mvnw -pl services/user-service -am test` 通过。

## 不做

- 不做超时自动关单（M2.5 延时消息）。
- 不做退款。

## 完成记录

日期：2026-09-20

提交：本次提交（`feat: 新增订单取消`）。

测试与接口证据：在 `boot-server/` 使用 Oracle JDK 25.0.4.1 执行 `./mvnw -q -pl services/user-service -am clean test`，27 份 Surefire 报告共 122 个测试，失败、错误、跳过均为 0；`git diff --check` 通过。

- 真实 HTTP：`POST /orders/{id}/cancel` 仅允许订单所有者操作；成功后状态由 `CREATED` 变为 `CANCELLED`，库存总量不变、锁定量按订单快照数量释放，可用量恢复。未登录返回 `401/40100`，非本人订单统一按不存在返回 `404/40400`。
- 状态门：PAID 订单与已取消订单再次取消均返回 `409/40900`；状态条件更新同时包含订单 ID、当前用户和 `CREATED`，失败后读取当前状态并返回受控错误。
- 原子回滚：双明细订单的第二条库存释放失败时，订单恢复为 `CREATED`，第一条已执行的释放也回滚；库存释放 SQL 使用 `locked_count >= quantity` 条件避免负数与重复释放。
- 分层与静态值审计：订单应用服务通过库存应用服务协作，不直接写库存表；`OrderStatus` 集中持有取消迁移规则，DDL 与测试断言保留映射/fixture 字面量。本卡未新增部署配置、错误码、角色码、权限码或共享存储键。
